# 章节工作流

使用 `browser_site_chaoxing__study` 读取当前目录和页签后推进。`read_only=true` 不操作页面，`current_only=true` 不跨小节。每次只启动唯一可见的播放器，先应用静音再播放，使用媒体事件等待。再次自动暂停时停止争抢播放器，核对弹题、验证或用户暂停。

视频结束后重新检查平台完成图标，不能将 `ended` 当成章节完成。目录中下一节必须来自新读取的可见叶子条目；未知状态、未读取的目录分页不能报告完成。

`needs_quiz` 时读取本章测验，生成答案后逐题填答复核；需交卷时遵守用户授权。`needs_discussion` 时读取讨论题目和少量匿名样本，由模型独立写回复；学习通使用 `browser_site_chaoxing__discussion` 的 `discussion_id` 和 `reply` 发布并回读，不复制他人的答案。

PDF/PPT/图书阅读在工作流中识别可见阅读器，按实际下一页、页码选择或滚动控件推进，尊重页面停留要求。也可用 `browser_site_chaoxing__read_document` 检查当前阅读器。阅读位置不推进时停止。翻页和滚动不代表平台学分登记，不直接调用伪造完成接口。

中断时保存语义检查点，不保存密码或过期选择器。`workflowPending=true` 可恢复等待；恢复先重新观察页面，遇到讨论发布不确定时禁止自动重发。

`start_course` 在一个仓库流程中完成登录、唯一课程匹配、打开目录与开始播放。课程列表必须先确认学生视角；同名课程按教师或刚观察的 id 区分，折叠文件夹和未读分页不能证明唯一匹配。

`chapter_range` 只接受已确认的整数目录编号。对于 2.1 等层级编号，先使用 catalog 的刚读取 id 打开具体章节，再以 `current_only=true` 执行，不猜测编号范围。没有计数、空任务列表、陈旧卡片或任务种类未知时返回待核对。只有当前所属任务 iframe 能被阅读、播放、答题或讨论；结束事件之后重新核对平台计数。

每次调用最多使用 480 条宿主命令，留出宿主 512 条限制的余量。已完成的任务不会重复开始；单次操作上限后返回 pending，后续从新观察和语义检查点继续。恢复发现课程变化时返回 workflow_mismatch，不覆盖原流程。
